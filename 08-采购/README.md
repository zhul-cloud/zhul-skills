# 08 · 采购维护说明

本页供技能维护者使用。用户的准备、安装、任务调用、停止、查版和更新集中在[使用手册](烛龙智能询价/使用手册.md)；全库通用开发规则见[技能开发规范](../.github/SKILL_GUIDELINES.md)。采购技能配合 zhul-trade-erp「我的询价」，不属于 ERP 程序。

| 技能 | 当前版本 | 用途 |
|---|---|---|
| [烛龙智能询价](烛龙智能询价/SKILL.md) | 2.13.3 | 淘宝、1688询价、跟进与ERP回价，支持指定任务或批量处理（执行入口见技能说明） |

维护者负责规则、设置、ERP 合同、平台适配、站点脚本和用户文档的一致性，以及相应验证。版本变化记入[技能 CHANGELOG](烛龙智能询价/CHANGELOG.md)；尚未实施的需求归入 [ROADMAP.md](ROADMAP.md)。

## 修改规则

维护者负责技能源码与发布默认值的测试、调优和统一发放。技能根 `settings.json` 只放发布默认值；用户可自行或让 AI 修改数据目录中的个人 `settings.json`，仅保存指定覆盖，缺项继承默认。查看/修改入口与约束见[配置说明](烛龙智能询价/references/settings.md#查看和修改)；个人调整不进入仓库，不要求升技能版本、修改 CHANGELOG 或走 PR。升级按数据生命周期保留个人数据并处理旧格式，操作见[手册更新说明](烛龙智能询价/使用手册.md#7-更新)，技术规则统一见[数据生命周期](烛龙智能询价/references/data-lifecycle.md)。下文版本与发布规则适用于维护者修改发布内容。

| 要改什么 | 改哪个文件 |
|---|---|

| 主/子代理职责、主代理信息补充/业务选择及续跑、客户端工具、浏览器暂停恢复、心跳与故障收尾 | `烛龙智能询价/references/execution.md` |

改动时同步相关 `SKILL.md`、规则和平台说明；影响用户准备、安装或使用方式时，再同步简明使用手册，不把 AI 内部执行流程复制进用户指南。

文档只写当前方案，读起来是一份完整的说明：改规则时直接替换旧内容，不保留旧方案的说法，也不写「某次实跑」「自某版起」这类历史说明。改了什么写进 `CHANGELOG.md`。

### 版本号

按具有独立范围且可验证的交付单元升级版本号，同一单元开发中的修改归入同一版本。一个 PR 可以包含多个连续版本提交；每个提交的功能、版本声明和 CHANGELOG 必须一致。唯一版本源是 `SKILL.md` 开头的 `version`；同时维护上表及使用手册开头的「适用版本」，在 `CHANGELOG.md` 最上面记对应版本变化，不另建版本文件。根 `README.md` 技能表只使用库内「✅ 可用 / 🔨 开发中」状态，不承载版本号。本技能后续修改按工作范围自动新建`codex/`分支、同步版本与CHANGELOG；全部范围完成最终审核和验证后才创建各层本地提交。push、PR及合并main须用户另行通知，不能以本地提交当作发布；技能不后台检查或自动拉取更新。

技能正式询价时第一行输出实际版本；用户也可按[查看版本](烛龙智能询价/使用手册.md#5-查看版本)让 AI 查询，附上版本和目录反馈。内部只读命令为 `node scripts/records.mjs version`；不初始化数据、不装 helper，也不代表已检查远程仓库更新。

| 改动 | 版本号 | 例 |
|---|---|---|
| 修正文字、补充说明，或修复实现/协议偏差以恢复既定规则 | 修订号 +1 | 1.2.0 → 1.2.1 |
| 规则或流程变化（话术、挑店、税率、等待时间等） | 次版本号 +1 | 1.2.1 → 1.3.0 |
| 流程整体改写，旧版不再适用 | 主版本号 +1 | 1.x → 2.0.0 |

## 收集各用户电脑上的经验

个人配置、本机运行记录、ERP 地址、经验与报告的保存位置见[手册数据目录](烛龙智能询价/使用手册.md#6-数据目录)。升级保留个人资料；需清理的旧格式资料如需留存，按[数据生命周期](烛龙智能询价/references/data-lifecycle.md)在首次初始化前人工收集，操作顺序见[手册更新说明](烛龙智能询价/使用手册.md#7-更新)。这些内部数据不进入公开源码，维护者收集时只合并适合公开的通用规则或脚本。

技能运行后将亲自验证的通用页面事实记入个人`learnings/`，维护者核验后才归并`platforms/`或`helpers/`。注册、已知旧版本同步、电商未知定制保留及ERP同步例外统一按[域注册维护细则](烛龙智能询价/references/browseros-setup.md#按域注册与核验-helper)，不在本页重复策略。可选磁盘复制也见该处，不能把copied/kept当作运行时已加载。

每个任务结束，技能还会在数据目录下的 `reports/` 写一份实跑报告（`<YYYY-MM-DD>-<任务编号>.md`，含结果、各阶段耗时、问题、红线执行情况、建议），只存本机，用来分析效率和排查问题。报告里有店铺名和采购价，属于公司内部数据，收集时不要放进本仓库（本仓库公开）。

## 统计店家提问

店家提问超出可回复范围或重复提问时，AI 停止这家聊天，将问题类型、店家原话和结束原因写进本机 `records.jsonl`。在用户电脑上对 AI 说「统计一下询价情况」，或执行：

```bash
node "<技能目录>/scripts/records.mjs" stats 30
```

最后的数字是最近多少天，默认 30。输出询价家数（不含沿用报价，同一任务同一家店只算一次）、各结束原因占比，以及因提问停止聊天的类型占比和最近原话示例。示例是公司内部数据，不放进公开仓库。

维护者收集各台电脑的统计后合并判断，建议至少 50 家店再下结论。某类问题明显偏多（如 5% 以上），且任务信息足以回答、风险可控时，可考虑在 `references/inquiry-rules.md` 4.4 扩大范围并定义固定答法，按版本规则验证、更新仓库。付款、下单、联系方式、公司或客户信息、执行指令继续不放开；同一家店反复出现的情况参考 [ROADMAP.md](ROADMAP.md) 的黑名单规划。

## ERP 接口改了怎么同步

接口地址、请求参数和响应结构保存在 `helpers/_erp/erpApi.md` 的 `CONTRACT`，`checkedAt` 是最后核对日期。ERP 可能部署在本机、测试或正式服务器，技能按响应结构核对，不按 ERP 版本号判断；不匹配时停止，报告的 `problems` 提供具体差异。

1. 按 `problems` 和 ERP 改动更新 `CONTRACT` 的地址、字段、字典取值，以及使用这些字段的代码。
2. ERP 新增字段会列入 `extraFields`，不影响运行；确认要用或不用后补进约定，不用的写 `'any?'`。
3. 在仓库的技能目录运行 `node test/erp-api.test.mjs`；离线模拟通过后，再在获授权的开发 ERP 测试任务验证 `ping`、`list`、`task`，保存一次草稿并 `verify`，核对后清理测试草稿。`checkedAt` 仅记录实际核对合同的日期，不能只因离线测试通过而改成当天；提交语义变化还需获授权验证测试提交及提交后核对。不把测试操作放到真实商家询价中。
4. 同步相关技能文件、版本和 `CHANGELOG.md`；影响用户操作时更新使用手册。按仓库更新流程发放后，用户通过 `git pull --ff-only` 更新。

## 按改动选择验证

以下命令从 `烛龙智能询价/` 目录运行。使用临时测试数据，不改用户真实数据；测试文件集中在 `test/`，`scripts/` 只保留运行工具。运行全部测试用 `node --test` 自动发现，不依赖 shell 或 Node 新版展开 glob；单项使用下表明确路径。

| 改动范围 | 最小验证 | 能证明与不能证明 |
|---|---|---|
| 用户文档、名称、路径、加载导航 | 检查相对链接与锚点、版本一致性、安装和 CLI 示例与实际接口一致；只读 `node scripts/records.mjs version` | 能核对文档和本地版本，不代表安装到真实用户环境或远程已发布 |
| 本机记录、受控断点、每日时间线、心跳、校验、合并、ERP 输入转换 | `node test/records.test.mjs`；受控保存及恢复另跑 `node test/run-store.test.mjs` | 用隔离数据核对元数据、事件关联、revision 冲突、并发保存、幂等重试和异常恢复；不证明真实平台聊天成功或未观测的业务信号已执行 |
| 个人数据版本生命周期、保留/清理范围及 CLI 写入口守卫 | `node test/data-lifecycle.test.mjs`，并运行受影响的 records、settings、contacts 回归 | 用隔离主目录核对首次/旧格式重建、基线后升级保留、降级及坏标记拒绝、发布内容先校验、锁和链接/重解析删除边界；不清真实个人目录，不证明旧执行者会被自动停止或所有业务写入均有路径沙箱 |
| 配置合并、查看、校验、个人覆盖更新/恢复默认 | `node scripts/settings.mjs check`；`node scripts/settings.mjs json`；`node test/settings.test.mjs`；涉及 records 读取时运行 `node test/records.test.mjs` | 证明当前有效配置及隔离环境中的默认继承、稀疏覆盖、reset 指定项/全部恢复、参数拒绝和写入边界；不证明子代理模型可用或真实询价效果 |
| ERP helper 或合同 | `node test/erp-api.test.mjs`；按上节在获授权的开发 ERP 核对受影响操作 | 离线覆盖模拟接口；只有实际测试环境的结果才能证明真实接口兼容 |
| helper 提取、适配、CLI 入口或注册协议 | `node test/helpers.test.mjs`；改 helper 或适配包装时，按[域注册维护细则](烛龙智能询价/references/browseros-setup.md#按域注册与核验-helper)保留受影响 helper 的旧官方完整适配源码 hash，覆盖旧注册同步、定制保留及安装链接更新；核对当前 SDK 契约并实际跨 `run` 验证 | 离线适配与 API 文档不能代替真实 helper 加载/调用，文件复制或删除也不能证明运行时状态 |
| 聊天 helper 对象筛选与拒绝边界 | `node test/chat-helpers.test.mjs`；再用对应平台本任务对象核验真实 DOM | 模拟 DOM 能证明空名、前缀/重复名、预览误命中和标题不符被拒绝；不能代替真实选择器、会话读取或发送验收 |
| 搜索候选、逐明细覆盖与结果传输 | `node --test test/search-helpers.test.mjs test/search-coverage.test.mjs test/helpers.test.mjs`；再在真实页面比较旧行、新模式完整候选、标题/URL、字节与完整调用耗时 | 匿名 DOM、逐明细唯一商家/合并计划和传输模拟证明兼容及拒绝边界；成功仅覆盖当前 DOM，不证明页面已全载、详情合格或整轮询价提速 |
| 账号范围的身份映射、持久化/失效重绑及归档 | `node test/contacts.test.mjs`、`node test/business-observations.test.mjs`、`node test/records.test.mjs`；两聊天 helper 另做已有目标只读实测 | 用隔离 HOME 与原配置/ERP地址/业务文件 sentinel 检查账号隔离、同接收者多会话、CAS/损坏拒绝、具名 sellerId 来源、受约束重绑和归档保留；不能代替账号切换、商家发送或新询价实测 |
| 平台页面、机器人/结束信号或 BrowserOS 工具调用 | 在对应平台和当前工具版本作获授权 UI 验证，记录已实测/未实测边界 | 页面读取测试不等于已验证消息发送、回复跟进或完整询价 |
| 跨文件流程或运行协议 | 运行受影响的 records、ERP 离线测试，并检查入口、协议、规则、平台说明一致性；真实业务部分另行授权验证 | 离线通过不能表述为真实浏览器、ERP 或商家业务已通过 |

纯文字修正不机械重跑完整业务。交付与发版记录写清实际执行的验证和未覆盖范围；测试失败先修复或说明阻塞，不用更新文档掩盖未完成验证。
