# 个人数据生命周期

个人目录以运行增强基线 `2.9.0` 为保留边界：有效版本标记为 `2.9.0` 或更高且不高于当前技能时，后续升级均保留整个 `<数据目录>`；仅无标记的遗留数据及低于基线的数据完整清理重建。不自动备份，不检查远程 Git、源码 hash，也不热更新正在运行的任务。用户操作见[手册「更新」](../使用手册.md#7-更新)。

## 初始化与版本判断

只有 `node "<技能目录>/scripts/records.mjs" init`（含显式 `--erp <地址>`）执行版本生命周期处理。版本取当前 `SKILL.md`，按三段语义版本比较；成功完成初始化（含旧 pending 恢复及 ERP 地址校验）后，最后写入 `<数据目录>/.skill-version.json`，表示最近成功初始化的技能版本：

```json
{ "schemaVersion": 1, "skillVersion": "2.11.0" }
```

| 数据状态 | `init` 行为 |
|---|---|
| 目录不存在或为空 | 创建当前版本所需目录和文件，写入版本标记 |
| 非空目录没有标记 | 视为遗留数据，完整清空后重建 |
| 有效标记低于 `2.9.0` | 完整清空后重建，仅执行一次 |
| 有效标记在 `2.9.0` 与当前版本之间（含两端） | 保留个人设置、ERP 地址、记录、断点、映射、经验、报告及其他内容，补齐必要目录；校验 ERP 地址、恢复兼容 pending，成功后推进标记。个人设置留给后续 `settings.mjs json` 检查 |
| 标记版本高于当前技能 | 拒绝回退初始化，不清理；使用相应新版 |
| 标记损坏、未知结构或版本无效 | 报错并保留数据，交维护者核对，不删标记绕过 |

保留时不改写历史记录；个人 `settings.json` 的稀疏覆盖继续生效，缺项继承新版默认值。原 run 身份及创建版本保持，跨版本恢复仍按[恢复协议](run-protocol.md#原-run-恢复与防重复)核对聊天和 ERP，保留数据不表示外部动作已确认或可以重发。无法识别的记录或 pending 保留现场并报错，不通过删记录修复。

获授权的旧格式重建覆盖个人 `settings.json`、ERP `config.json`、`contacts.json`、`runs/` 断点、询价/处理历史、`learnings/`、`reports/` 及目录内其他内容；原断点、防重复与映射随之清除。BrowserOS 登录和已注册 helper、ERP 服务器数据不受影响。

脚本先校验当前 SKILL 版本、发布默认值及显式 ERP 参数，再处理生命周期；这些发布内容或新输入非法时不清旧数据。旧格式清理不解析旧个人设置或 ERP 配置。保留范围内的坏配置不触发清理：坏 ERP 配置使初始化失败且不推进标记；个人设置错误按[配置校验与修复](settings.md#校验边界)处理。

## AI 调用顺序

- **正式询价**：先确认旧执行者已停，执行 `records.mjs init`，再执行 `settings.mjs json` 校验并读取有效配置；通过后输出运行提醒，再补齐 ERP 地址、准备 BrowserOS。
- **明确修改个人配置或 reset**：先确认具体项/值或范围清楚，且询价执行者已停，再 `init` → 读取当前配置 → 执行指定修改。`reset` 本身只移除指定个人覆盖；`reset --all` 不动 ERP 或业务记录。旧格式清理属于 `init`，不得混称 reset 的作用。
- **明确修改 ERP 地址**：沿用 `records.mjs init --erp <地址>`；先确认执行者已停及地址意图清楚。
- **仅查看**：`version`、settings 表格/`check`/`json`、`stats`、contacts `lookup` 只读现存数据，不运行 `init`，不宣称当前版本已初始化。读取文件、导入模块本身不触发删除。

`init` 返回 `dataRebuilt:false` 时说明已保留个人数据；返回 `true` 时告知「已为当前版本初始化/重建空白个人数据目录」，说明当前使用新版默认设置。用户已有明确个人设置要求时按配置流程保存，不新增可选配置问答阻塞询价。仅正式询价缺 ERP 地址，或明确修改 ERP 却缺值时，按[既有提问分支](execution.md#何时提问答后回到哪里)补齐；显式传入的地址不重复收集。独立 settings 修改/reset 允许 `erpUrl:null`，完成指定配置即结束。旧格式重建已获授权，不另加一次清空确认。初始化报错停止依赖动作，不手工删标记、锁或旧文件绕过。

## 并发与删除范围

生命周期短锁位于同一系统主目录的 `.zhul-trade-sourcing.lifecycle.lock`，在数据目录之外。其他 CLI 写入口持锁并要求目录已按当前版本初始化；尚未初始化或标记不一致时拒绝，不能顺带重建。较新标记也阻止旧技能写入。升级时现有 settings/contacts 写锁阻止推进标记；锁不自动删除。records 写入口对锁作有限等待，其余入口按原锁规则报忙。断点、每日时间线和 pending 恢复见[受控保存与事件](run-protocol.md#受控保存与事件)：兼容版本事务按原身份、版本和 hash 恢复，恢复后才推进目录标记；未知版本、损坏、第三态冲突及越界路径均保留现场并停止。

锁仅协调支持该协议的 CLI，不能停止旧代码或 AI 直接写文件；更新前必须确认全部旧执行者已停。无标记或低于基线的资料如需留存，须在首次 `init` 前人工收集，清理后无法追回。清理前完整检查目录、父链、锁和链接/重解析边界，删除前再核对目录项身份；这些检查限定生命周期删除范围，不是所有业务写入的通用路径沙箱。
