# 1688 操作说明

本页记录1688页面特例；登录、验证及恢复按[执行协议](../references/execution.md#暂停与恢复)，helper注册和跨run加载按[准备协议](../references/browseros-setup.md#按域注册与核验-helper)。运行时使用`zhul_1688_`前缀，不能绕过旧普通名内容核对。页面变化或标「未实测」的做法须现场核验，验证后记入[本机经验](../references/run-protocol.md#本机经验)。脚本不发消息；打开会话会清除未读状态。

| 站点 | 脚本 | 作用 |
|---|---|---|
| s.1688.com | `helpers["zhul_1688_searchCandidates"](browser, pageId, { model, mode: "current-dom" })` | 当前 DOM 的全部候选；每项 `legacy` 为 `[排名, 商品ID, 标价, 公司名, 型号匹配, 疑似非全新, 广告]`，另带独立 `title`、`productUrl`；广告可为空 ID |
| air.1688.com | `helpers["zhul_1688_imPreviews"](browser, pageId, keys)` | 按完整列表名精确且唯一匹配的预览，不点开；不以预览文字匹配店铺 |
| air.1688.com | `helpers["zhul_1688_imOpenAndRead"](browser, pageId, key)` | 按完整列表名唯一打开，核对标题、唯一 active 父项及所有消息归属并等富消息就绪，返回最近 20 条、每条最多 300 字符消息、`preview` 和 `ended` |

## 1 登录

- 首页：`https://www.1688.com`。
- 首页「立即登录」及cookie `__cn_logon__`可辅助判断登录；确认未登录后按[暂停与恢复](../references/execution.md#暂停与恢复)请求用户登录1688买家账号，交回核验后续原任务。

## 2 搜索

1. 在自己的标签页里用地址打开货源直达里的 1688 链接（`https://s.1688.com/selloffer/offer_search.htm?charset=utf8&keywords=...`），不在 ERP 页面上点击。技能生成的关键词按 UTF-8 编码，入口明确带 `charset=utf8`。导航后核对实际搜索词、页面状态及本次结果归属；URL 已变或已有商品卡片不足以证明新结果就绪。无法核实时保留未完成，不能记无货。
   已有断点的链接和 ERP 基线保持原样；若导航后实际搜索词不符，只在能从原链接明确、无歧义地解码得到原始 UTF-8 关键词时，用网站正常搜索框提交该原词，并重新核对搜索词及结果归属。原编码或词义不明时不猜；乱码结果不能当无货，也不能据此重建 run。
2. 用表中的对象调用，`model` 传原型号；读取当前 DOM 全部候选，不能只读旧字符串入口的前 20 条。独立商品标题来自卡片的 `titleText--` 节点，不能把带 `title` 属性的公司名当商品标题；`legacy` 公司名仍是整卡文本提取的提示，须在详情核实全称。覆盖和失败按[共同候选规则](../references/inquiry-rules.md#找店与挑店)处理；¥10、¥12 等占位价仍按第 3 节排除。
3. 按第 3 节从这条链接的结果里挑店，家数按 `shopsPerLink`。挑完在同一个标签页打开下一条 1688 链接，同样挑店，直到所有 1688 链接都做完；同一原型号的前面链接里判断过的商品 ID 直接跳过。不同型号可复用仍有效的同一商品/店铺页面字段，仍须逐型号核对完整型号、后缀和规格，不能因商品 ID 相同略过该型号核验；选择 SKU 后的价格等状态须当前核验。候选公司名须与已核公司全称对应后才用于同店跳过，不能凭模糊卡片标签判定同店。所有链接均已确认覆盖且没有型号匹配的店，才按共同规则处理无货；不能把读取失败或尚未加载的候选当作无货。

## 3 挑店

按 [inquiry-rules.md](../references/inquiry-rules.md) 第 3 节，结合页面特点：

1. **广告位**：链接是 `dj.1688.com/ci_bb?...`，或卡片 class 含 `ad-common`，排除。
2. **型号核对**：标题常混写相近型号（如 `1HG40` 与 `1AG40`），也常用字母 `O` 代替数字 `0`（`OXBO`）。脚本会移除符号并将 `O` 按 `0` 匹配，`型号匹配` 为 1 仅是候选提示，仍须在商品页逐字核对完整订货号及后缀。
3. **占位价**：¥10、¥12 这类明显不可能的标价，以及标题写「议价」的，排除。
4. **页面标价只作参考**：同一商品页有多个规格，会出现其他规格的低价；报价以店家回复为准。
5. **店铺信息**：商品页有「入驻 N 年」「主营」「店铺回头率」「店铺好评率」「承诺 24/48 小时发货」「运费 ¥N 起」。主营不是工控的、承诺 48 小时发货的、入驻 1 年且回头率 0% 的往后排。
6. **公司名**：以商品页和聊天页右侧档案里的公司全称为准，同一型号的不同链接搜到同一家公司只问一次；聊天名常和公司名不同（如「光穗网络科技666」对应「光穗网络科技(上海)有限公司」）。
7. **商品页逐个打开，一次最多 2 个**。一次同时打开多个商品页可能出现「CAPTCHA Verification」，按[共享验证规则](../references/execution.md#普通滑块仅尝试一次)分流，不把所有验证都当普通拖动条。

### 商品详情一次读取

当前任务商品页已就绪且归属明确后，在同一次 `page.evaluate` 执行下面函数，传 `{ itemId, model }`。一次取得独立标题、精确 SKU、属性原文、公司全称及评级/履约/回头率/发货原文；不以标题含型号放行。属性行仅作待核线索，不把任意描述行里的目标文字当型号属性。返回字段不是最终商品规格或商家身份结论，仍按[共同挑店规则](../references/inquiry-rules.md#找店与挑店)核对。

```js
({ itemId, model }) => {
  // zhul-product-fields: 1688
  if (typeof itemId !== 'string' || !/^\d+$/.test(itemId) || typeof model !== 'string' || !model.trim()) return { ok: false, error: 'SKILL_INPUT' };
  const url = new URL(location.href);
  if (!['http:', 'https:'].includes(url.protocol) || url.username || url.password || url.hostname !== 'detail.1688.com' || url.pathname !== '/offer/' + itemId + '.html') return { ok: false, error: 'PRODUCT_IDENTITY' };
  const visible = (e) => e.getClientRects().length > 0;
  if ([...document.querySelectorAll('.nc_scale,.nc_wrapper,#nocaptcha,[class*=captcha]')].some(visible)) return { ok: false, error: 'VISIBLE_VERIFICATION' };
  const titles = [...document.querySelectorAll('.title-content h1')].filter(visible);
  const shops = [...document.querySelectorAll('a.shop-company-name')].filter(visible);
  const sku = [...document.querySelectorAll('.item-label')].filter(visible).map((e) => e.textContent.trim());
  const rows = [...document.querySelectorAll('tr.ant-descriptions-row')].filter(visible).map((e) => e.innerText.replace(/\s+/g, ' ').trim());
  if (titles.length !== 1 || !titles[0].innerText.trim() || shops.length !== 1 || !sku.length && !rows.length) return { ok: false, error: 'PRODUCT_FIELDS_UNAVAILABLE' };
  const shop = shops[0], shopName = shop.innerText.trim(), header = shop.closest('.shop-container');
  let shopUrl;
  try { shopUrl = new URL(shop.href); } catch { return { ok: false, error: 'PRODUCT_FIELDS_UNAVAILABLE' }; }
  if (!shopName || !header || !['http:', 'https:'].includes(shopUrl.protocol) || shopUrl.username || shopUrl.password || !/(^|\.)1688\.com$/.test(shopUrl.hostname)) return { ok: false, error: 'PRODUCT_FIELDS_UNAVAILABLE' };
  const exactSku = sku.filter((s) => s.replace(/\s/g, '') === model);
  const hasExactSku = exactSku.length > 0;
  return { ok: hasExactSku, ...(hasExactSku ? {} : { error: 'PRODUCT_MODEL_UNCONFIRMED' }), itemId, title: titles[0].innerText.trim(), exactSku, attributeRows: rows,
    shopName, shopUrl: shopUrl.origin + shopUrl.pathname, shopHeader: header.innerText.trim(),
    shipping: [...document.querySelectorAll('a.delivery-limit')].filter(visible).map((e) => e.innerText.trim()) };
}
```

标题含目标型号但独立 SKU 不对应时，片段返回 `PRODUCT_MODEL_UNCONFIRMED`；属性原文须核清独立型号字段后才可用于判断，不能按描述词命中补成合格。缺字段按实际就绪状态补核，不固定等候。URL 的商品 ID 不单独证明旧 DOM 已更新，须核实当前商品与店铺入口对应；已有商家身份按下文具名来源交叉核对。验证及读取失败按[暂停与恢复](../references/execution.md#暂停与恢复)处理，选择器未命中不等于没有验证。

## 4 聊天页：始终只保留一个

1. **给新的一家发询价**：在商品页点「客服」（没有 `href` 的链接，snapshot 里是 `link "客服"`；店铺头部和商品区各有一个，点哪个都可以）。点击后会新开标签页 `https://air.1688.com/app/ocms-fusion-components-1688/def_cbu_web_im/index.html?touid=cnalichn<聊天名>&offerId=<商品ID>&...`，并直接进入这家的会话。
2. 新聊天页出现后，**立刻关掉本次自己打开的同平台旧聊天页**，在新页里发送。新页左侧的会话列表里有之前所有的会话，查看回复也只用这一个页面。关掉旧页后新页保持连接（已实测）；关掉旧页后在新页发送还未实测，首次照做时发送后读回核对。
3. 点「客服」带出的页面可能显示为用户标签；归属、清理及导航后的状态核对统一按[共享浏览器规则](../references/execution.md#共享浏览器)执行。
4. **聊天设置弹窗**：账号第一次点「客服」时会弹出「请选择你优先使用的聊天工具：1688网页版聊天 / 源采客户端」，选择会保存为账号设置。按[执行协议「暂停与恢复」](../references/execution.md#暂停与恢复)请求 BrowserOS 接管，让用户在页面选择并确认；说明「源采客户端」无法由 AI 在浏览器里询价。Hand back 后核实弹窗已处理且网页聊天可用，再继续；不通过主聊天选择框代替页面接管。

## 5 发送

1. 聊天内容在同源 iframe（`def_cbu_web_im_core`）里，用 `iframe.contentDocument` 读写。外层页面顶部还有一个 1688 搜索框（无障碍树里的第一个 `textbox`），**不是聊天输入框**，不要往里输入。
2. 聊天区标题是 `.conversation-header`（聊天名 + 「进店」），右侧档案的 `.nameLine` 是公司全称。**发送前核对**标题中的完整身份与目标聊天名或已核实客服别名一致，并核对公司档案；独立「进店」控件（当前页面为 `.go-shop-container` 内的 `div.go-shop`）是界面文字，不作为身份。不能以包含关系放行，店铺/公司与客服子账号不同先依据本任务商品页进入的会话核实并记录映射。
3. **输入框是 `pre.edit[contenteditable="true"]`**。页面里同时有多个 `pre.edit`，其余的是 `contenteditable="false"`，只用 `pre.edit` 选择会选错。
4. 输入方法：在 iframe 里先 `focus()` iframe，再 `focus()` 输入框，确认 `activeElement` 就是它，然后用 `page.insertText(话术)`。输入后核对输入框文字和字数计数（`N / 500`）。
5. 点聊天区的「发送」按钮（无障碍树里的 `button "发送"`；「发送链接」是发商品卡片，不要点）。
6. 发送后读回：会话里出现刚发的内容，标题仍是目标店，字数计数回到 `0 / 500`。发送后输入框里可能残留文字，以字数计数为准，不要因此重复发送。
7. 自己发出的消息后面显示「未读 / 已读」，可以看出店家是否已读。

## 6 查看回复

- 已核实会话按[当前账号身份映射](../references/identity-mapping.md)复用，scope 来自聊天 iframe 的 currentLoginId；缓存精确读仍核全部消息及公司档案。名称预览歧义/缺项不表示无回复，可转已核 binding 的 ID 读取。商家回复的 sender 可能是客服子账号，不等于目标 recipient 或独立商家 ID。
- 会话列表项是 iframe 里的 `.content`（内容是「聊天名 + 时间 + 最后一条消息预览」）。轮询时用 `zhul_1688_imPreviews` 只读本次几家的预览，不点开。
- 预览变了，用 `zhul_1688_imOpenAndRead` 点开读消息 `.message-item`（自己发的带 `self`；对方的聊天名可能带子账号，如「上海丽丞自动化有限公司:小双」）。点开会话即标为已读。
- 打开读取以页面变化触发核验，完整列表名对应的 `.content` 必须位于唯一 active 的 `.conversation-item` 中；标题只去除独立「进店」控件，不猜客服别名。每条消息 DOM 的有限 React Fiber 链中，当前及有值的 alternate 消息 `conversationCode` 均须与 active 的非空 ID 一致，全部通过后才检查正文。排除独立的 `message-item-line`，不把空分隔行当消息。
- 已绑定的富消息仍可能先显示精确的「暂不支持的消息类型」占位，须等占位消失再返回全部消息；不返回看似完整的部分正文。页面就绪最多等 2200ms，届时按实际阻塞返回 `timedOut:true` 和 `CHAT_IDENTITY`、`CHAT_MESSAGES_UNAVAILABLE`、`CHAT_BINDING_UNAVAILABLE`、`CHAT_MESSAGE_IDENTITY` 或 `CHAT_MESSAGES_RENDERING`，iframe 不可用为 `CHAT_DOM`。失败只表示未安全读到目标消息，不能当作无回复、无货或没有结束信号，转人工定位目标区域，不降低核验。店家回复等待仍按业务规则和本次有效设置计时。
- 公司档案独立加载，消息就绪不表示 `company` 已就绪。读取前须在当前唯一 `.information-tab` 的有限 Fiber 链中核实当前及有值的 alternate `activeConversationName` 为目标完整列表名、`activeDomain` 严格为 `cnalichn` 且一致；唯一 `.next-loading` 的 `visible` 须明确为 `false`、无 `next-open`，唯一 `.nameLine` 非空后才一起返回公司和消息。档案缺失、身份冲突或仍在加载时继续在同一 2200ms 截止内等待；超时分别返回 `CHAT_PROFILE_UNAVAILABLE`、`CHAT_PROFILE_IDENTITY` 或 `CHAT_PROFILE_RENDERING`，不以空公司或旧档案冒充成功。
- 聊天 helper 的字符串 `key` / `keys` 必须是本任务完整列表名；已核实标题别名时，打开函数可传 `{ contact: "完整列表名", headerName: "已核实标题身份" }`。名称节点或首独立文本行须精确唯一，预览中提及其他店名不算命中。空名、零/多匹配或标题不符不读取消息；选择器兼容性须在实际页面核验，失败按快照检查目标区域，不算无回复、不退回整页截取。
- 读整页文字时会带出账号其他会话的预览：只解析目标店铺的会话，其他内容不解析、不记录。

### 机器人回复

以下消息不算人工回复，继续等人工，计时不重置：

- 消息下方带「智能客户专员」标记的（如「您好，稍等」）。
- 进入聊天时自动发出的店铺介绍（「本公司诚信经营，代理销售……」）。
- 平台提示「商家长时间没有回复，平台已通知商家，请耐心等待」。

### 结束信号

- **「客服评价邀请」**：店家客服主动结束了本次聊天。这家立即结束，按已有信息记录，不再发送任何消息（包括追问和道谢）。
- 它**只出现在会话列表的预览里**，不在会话的消息（`.message-item`）里。判断是否结束要看列表预览：`zhul_1688_imPreviews` 的结果，或 `zhul_1688_imOpenAndRead` 返回的 `preview` / `ended`。
- 是否发出由店家客服决定，不一定会出现；没出现不代表聊天还在进行，这家照常按计时和信息是否齐全结束。

## 7 店家回复的特点

- 人工客服大多 30 秒到 1 分钟内报价；有的店只有智能客服回复，人工一直不看消息。
- 常只回一个数字（如「2300」）或几个词（「2000单价 现货 全新」）；回答含税时可能只写「含税」，不说票种。
- 回复里常有拼音输入错字，如「型号 含税」是「现货 含税」，按规则第 6 节「错别字和简写」处理。
- 报价可能高于搜索页标价。

## 8 已知风险

- 短时间打开多个商品页可能触发验证。按[共享验证规则](../references/execution.md#普通滑块仅尝试一次)处理，之后逐个打开。

恢复、未知发送或完整报价证据不足时，另行只读核对对应会话；不能把截取缺失当成未发或无报价。

### 具名商家页证据

仅在本任务实际「进店」并核实归属后的店铺页取公开初始化数据的具名字段，不读取或输出整份全局数据。当前证实 `window.pageData.globalData.sellerId` 可与聊天 recipient.targetId 对照，`buyerId/buyerIsLogin` 可与刚核实的 self 买家 ID 交叉；`memberId` 可独立保留，不拆出数字。该数字买家证据仅来自这次商家页，不表示聊天账号查询随时有数字 UID。

下列片段参数取刚通过聊天身份守卫的 recipient.targetId 和 buyer.targetId。成功值可附到 identity.businessIdentity 后交 `contacts remember/rebind`；缺来源、跨账号、店铺 domain 不符或 ID 矛盾均保持 null，不把另一家公司同名当关联证据。

```js
// zhul-business-observation: 1688；在已核实店铺页 page.evaluate 中执行。
({ recipientId, buyerId }) => {
  const g = window.pageData?.globalData;
  const id = (value) => typeof value === 'string' && value.trim() === value && value ? value
    : Number.isSafeInteger(value) && value > 0 ? String(value) : null;
  const seller = id(g?.sellerId), buyer = id(g?.buyerId);
  if (g?.buyerIsLogin !== true || seller !== recipientId || buyer !== buyerId || g.domain !== location.hostname) return null;
  if (!/(^|\.)1688\.com$/.test(location.hostname) || !['http:', 'https:'].includes(location.protocol)) return null;
  if (g.memberId != null && (typeof g.memberId !== 'string' || !g.memberId.trim())) return null;
  return { type: 'sellerId', value: seller, source: 'window.pageData.globalData.sellerId', sourceUrl: location.href,
    shopUrl: location.origin + '/', observedAt: new Date().toISOString(), buyerId: buyer, buyerIsLogin: true,
    ...(g.memberId == null ? {} : { memberId: g.memberId }) };
}
```
