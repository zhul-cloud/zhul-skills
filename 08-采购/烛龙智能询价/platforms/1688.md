# 1688 操作说明

本页页面定位与页面现象最近核对日期为 2026-10-15；标「未实测」的条目是按已核对页面行为推定的做法，首次照做时要核对结果，验证后去掉标记。1688 改版后某条失效时，按实际情况操作，并在本机经验文件里记下（见 [run-protocol.md「本机经验」](../references/run-protocol.md#本机经验)）。

技能自带的站点脚本在 `<技能目录>/helpers/`，按[按域注册与核验 helper](../references/browseros-setup.md#按域注册与核验-helper)同时检查普通名和前缀名、比较并保留本机改进，确定性适配后在对应域 `saveHelper`，下一次 `run` 核验后调用。运行时名称带 `zhul_1688_` 前缀，避免与淘宝同名 helper 相互覆盖；不能以新前缀绕过旧普通名的内容差异。连接故障由主代理恢复，平台代理不启动浏览器。脚本不发消息、不提交；搜索和预览只读，打开会话会清除未读状态。

| 站点 | 脚本 | 作用 |
|---|---|---|
| s.1688.com | `helpers["zhul_1688_searchCandidates"](browser, pageId, model)` | 搜索结果前 20 条的精简候选：`[排名, 商品ID, 标价, 公司名, 型号匹配, 疑似非全新, 广告]`；广告位的商品 ID 为空 |
| air.1688.com | `helpers["zhul_1688_imPreviews"](browser, pageId, keys)` | 按完整列表名精确且唯一匹配的预览，不点开；不以预览文字匹配店铺 |
| air.1688.com | `helpers["zhul_1688_imOpenAndRead"](browser, pageId, key)` | 按完整列表名唯一打开，核对标题身份后，返回最近 20 条、每条最多 300 字符消息、`preview` 和 `ended` |

站点脚本只在 `run` 开始时、按当时已打开页面的域名加载：先打开搜索页或聊天页，**下一次** `run` 才能调用对应脚本。

点「客服」打开的本任务聊天页可能显示为用户页，先核实来源和归属；热加载不可用时的安全恢复及已保存源码调用见[域注册流程](../references/browseros-setup.md#按域注册与核验-helper)。不能只凭 `not a function` 判断脚本未安装，也不靠重复重启解决。

所有登录、验证码、账号设置等人工协助统一按 [执行协议「暂停与恢复」](../references/execution.md#暂停与恢复)申请并消费 BrowserOS 人助；只中断受影响平台，不能记成无货。每次发送含更正先保存意图，读回确认后落盘；结果未知先查聊天证据。恢复先读停止期间的新回复，不重问已完成平台或真正业务结束的店。

## 1 登录

- 首页：`https://www.1688.com`。
- 未登录时首页有「立即登录」，cookie `__cn_logon__=false`；登录后为 `true`。遇到未登录就停下，请用户在 BrowserOS neo 里登录 1688 买家账号。

## 2 搜索

1. 在自己的标签页里用地址打开货源直达里的 1688 链接（`https://s.1688.com/selloffer/offer_search.htm?keywords=...`），不在 ERP 页面上点击，等出现商品卡片（指向 `detail.1688.com/offer/<商品ID>.html` 的链接）。
2. 调用 `zhul_1688_searchCandidates` 读候选，第三参传原型号字符串。不要把整页文字或大段结果直接返回：结果太大时 BrowserOS 会写进文件、只给文件引用。脚本带出的 ¥10、¥12 这类占位价，按第 3 节排除。
3. 按第 3 节从这条链接的结果里挑店，家数按 `shopsPerLink`。挑完在同一个标签页打开下一条 1688 链接，同样挑店，直到所有 1688 链接都做完（见 [inquiry-rules.md「找店与挑店」](../references/inquiry-rules.md#找店与挑店)）；前面链接里判断过的商品 ID 直接跳过，候选里的公司名和这个型号已挑出的公司相同的也直接跳过。所有链接都没有型号匹配的店，该型号在 1688 按无货处理。

## 3 挑店

按 [inquiry-rules.md](../references/inquiry-rules.md) 第 3 节，结合页面特点：

1. **广告位**：链接是 `dj.1688.com/ci_bb?...`，或卡片 class 含 `ad-common`，排除。
2. **型号核对**：标题常混写相近型号（如 `1HG40` 与 `1AG40`），也常用字母 `O` 代替数字 `0`（`OXBO`）。脚本会移除符号并将 `O` 按 `0` 匹配，`型号匹配` 为 1 仅是候选提示，仍须在商品页逐字核对完整订货号及后缀。
3. **占位价**：¥10、¥12 这类明显不可能的标价，以及标题写「议价」的，排除。
4. **页面标价只作参考**：同一商品页有多个规格，会出现其他规格的低价；报价以店家回复为准。
5. **店铺信息**：商品页有「入驻 N 年」「主营」「店铺回头率」「店铺好评率」「承诺 24/48 小时发货」「运费 ¥N 起」。主营不是工控的、承诺 48 小时发货的、入驻 1 年且回头率 0% 的往后排。
6. **公司名**：以商品页和聊天页右侧档案里的公司全称为准，同一型号的不同链接搜到同一家公司只问一次；聊天名常和公司名不同（如「光穗网络科技666」对应「光穗网络科技(上海)有限公司」）。
7. **商品页逐个打开，一次最多 2 个**。一次同时打开多个商品页会出现「CAPTCHA Verification」，需要用户手动处理。

## 4 聊天页：始终只保留一个

1. **给新的一家发询价**：在商品页点「客服」（没有 `href` 的链接，snapshot 里是 `link "客服"`；店铺头部和商品区各有一个，点哪个都可以）。点击后会新开标签页 `https://air.1688.com/app/ocms-fusion-components-1688/def_cbu_web_im/index.html?touid=cnalichn<聊天名>&offerId=<商品ID>&...`，并直接进入这家的会话。
2. 新聊天页出现后，**立刻关掉本次自己打开的同平台旧聊天页**，在新页里发送。新页左侧的会话列表里有之前所有的会话，查看回复也只用这一个页面。关掉旧页后新页保持连接（已实测）；关掉旧页后在新页发送还未实测，首次照做时发送后读回核对。
3. 点「客服」打开的标签页在 BrowserOS 里会显示为用户的标签页，但它是本次询价打开的，按上面的步骤照样关闭，结束时也要关掉最后一个。
4. **聊天设置弹窗**：账号第一次点「客服」时会弹出「请选择你优先使用的聊天工具：1688网页版聊天 / 源采客户端」，选择会保存为账号设置。按[执行协议「暂停与恢复」](../references/execution.md#暂停与恢复)请求 BrowserOS 接管，让用户在页面选择并确认；说明「源采客户端」无法由 AI 在浏览器里询价。Hand back 后核实弹窗已处理且网页聊天可用，再继续；不通过主聊天选择框代替页面接管。

## 5 发送

1. 聊天内容在同源 iframe（`def_cbu_web_im_core`）里，用 `iframe.contentDocument` 读写。外层页面顶部还有一个 1688 搜索框（无障碍树里的第一个 `textbox`），**不是聊天输入框**，不要往里输入。
2. 聊天区标题是 `.conversation-header`（聊天名 + 「进店」），右侧档案的 `.nameLine` 是公司全称。**发送前核对**标题中的完整身份与目标聊天名或已核实客服别名一致，并核对公司档案；独立「进店」控件（当前页面为 `.go-shop-container` 内的 `div.go-shop`）是界面文字，不作为身份。不能以包含关系放行，店铺/公司与客服子账号不同先依据本任务商品页进入的会话核实并记录映射。
3. **输入框是 `pre.edit[contenteditable="true"]`**。页面里同时有多个 `pre.edit`，其余的是 `contenteditable="false"`，只用 `pre.edit` 选择会选错。
4. 输入方法：在 iframe 里先 `focus()` iframe，再 `focus()` 输入框，确认 `activeElement` 就是它，然后用 `page.insertText(话术)`。输入后核对输入框文字和字数计数（`N / 500`）。
5. 点聊天区的「发送」按钮（无障碍树里的 `button "发送"`；「发送链接」是发商品卡片，不要点）。
6. 发送后读回：会话里出现刚发的内容，标题仍是目标店，字数计数回到 `0 / 500`。发送后输入框里可能残留文字，以字数计数为准，不要因此重复发送。
7. 自己发出的消息后面显示「未读 / 已读」，可以看出店家是否已读。

## 6 查看回复

- 会话列表项是 iframe 里的 `.content`（内容是「聊天名 + 时间 + 最后一条消息预览」）。轮询时用 `zhul_1688_imPreviews` 只读本次几家的预览，不点开。
- 预览变了，用 `zhul_1688_imOpenAndRead` 点开读消息 `.message-item`（自己发的带 `self`；对方的聊天名可能带子账号，如「上海丽丞自动化有限公司:小双」）。点开会话即标为已读。
- 聊天 helper 的字符串 `key` / `keys` 必须是本任务完整列表名；已核实标题别名时，打开函数可传 `{ contact: "完整列表名", headerName: "已核实标题身份" }`。名称节点或首独立文本行须精确唯一，预览中提及其他店名不算命中。空名、零/多匹配或标题不符不读取消息；选择器兼容性须在实际页面核验，失败按快照检查目标区域，不算无回复、不退回整页截取。
- 读整页文字时会带出账号其他会话的预览：只解析目标店铺的会话，其他内容不解析、不记录。

### 机器人回复

以下消息不算人工回复，继续等人工，计时不重置：

- 消息下方带「智能客户专员」标记的（如「您好，稍等」）。
- 进入聊天时自动发出的店铺介绍（「本公司诚信经营，代理销售……」）。
- 平台提示「商家长时间没有回复，平台已通知商家，请耐心等待」。

### 结束信号

- **「客服评价邀请」**：店家客服主动结束了本次聊天。这家立即结束，按已有信息记录，不再发送任何消息（包括追问和道谢）。
- 它**只出现在会话列表的预览里**，不在会话的消息（`.message-item`）里。判断是否结束要看列表预览：`zhul_1688_imPreviews` 的结果，或 `zhul_1688_imOpenAndRead` 返回的 `preview` / `ended`。
- 是否发出由店家客服决定，不一定会出现；没出现不代表聊天还在进行，这家照常按计时和信息是否齐全结束。

## 7 店家回复的特点

- 人工客服大多 30 秒到 1 分钟内报价；有的店只有智能客服回复，人工一直不看消息。
- 常只回一个数字（如「2300」）或几个词（「2000单价 现货 全新」）；回答含税时可能只写「含税」，不说票种。
- 回复里常有拼音输入错字，如「型号 含税」是「现货 含税」，按规则第 6 节「错别字和简写」处理。
- 报价可能高于搜索页标价。

## 8 已知风险

- 短时间打开多个商品页会触发验证码。遇到就停下请用户处理，之后逐个打开。

恢复、未知发送或完整报价证据不足时，另行只读核对对应会话；不能把截取缺失当成未发或无报价。
