# settings.json 配置说明

`settings.json` 放在技能根目录，保存询价时所有可调的数字和开关。技能文档里只写键名，具体取值一律以这个文件为准。

## 谁来改

设置由技能维护者统一维护：在开发中测试、调优后定版，随新版技能发放。**采购不要自行修改**；觉得某项不合适（比如等待时间太长、道谢说法不自然），反馈给维护者，测试后在下一版统一调整。

维护者修改时：

1. 只改冒号后面的值，**不要改键名**，不要删逗号、引号和大括号、方括号。
2. 改完让 AI 检查：「帮我检查一下询价设置」。AI 会读出每一项的当前值；格式写错时会指出哪一行。
3. 新开一个 AI 会话才会生效；正在运行的询价任务不受影响。
4. 修改后同步更新 `使用手册.md` 第 5 节的设置表，按 `08-采购/README.md` 的规则升级版本号，并在 `CHANGELOG.md` 写明改了什么。

> JSON 文件里不能写注释，说明都放在本文。

## 当前默认值

```json
{
  "confirmBeforeSend": false,
  "shopsPerChannel": { "min": 3, "max": 3 },
  "firstHumanReplyMinutes": 5,
  "followUpReplyMinutes": 3,
  "pollIntervalSeconds": { "min": 10, "max": 30 },
  "maxFollowUpsPerShop": 1,
  "dedupeDays": 7,
  "priceOutlierPercent": 30,
  "thankYouMessages": [
    "好的，谢谢您！",
    "收到，麻烦您了，谢谢。",
    "明白了，辛苦了，谢谢！",
    "好的，了解了，感谢！",
    "谢谢您的回复，麻烦了。"
  ],
  "subagents": {
    "enabled": true,
    "claude": { "model": "sonnet", "effort": "medium" },
    "codex": { "model": "gpt-6.1-sol", "effort": "medium" }
  }
}
```

## 各项说明

### confirmBeforeSend：发询价前是否先让采购确认

| 取值 | 效果 |
|---|---|
| `false`（默认） | **自主执行**。AI 挑好店直接发询价，全程不停下来问，最后统一汇报 |
| `true` | AI 挑好店后，先把各平台的店铺清单和要发的话术列给采购，得到同意后再发。一个任务只确认一次 |

- 只管「发询价」这一步。登录失效、验证码、账号异常这类情况，不论取值如何，AI 都会停下来请采购处理。

### shopsPerChannel：每个平台询价几家店

- `min`：至少问几家；`max`：最多问几家。两个数相同就是固定家数。默认固定 3 家。
- 按平台分别计算：一个任务同时在淘宝、1688 询价时，每个平台各问这么多家。
- 型号匹配的店多于 `max` 时，从排名靠前、有成交的店里挑；少于 `min` 时，有几家问几家，不拿错型号或重复店铺凑数。
- 问完不补店：挑出的店有没回复的，不再另找新店补问。
- 建议范围：1 到 5。家数越多，等回复和整理的时间越长，短时间内发消息过多也更容易触发平台验证。

### firstHumanReplyMinutes：等首次人工回复的时间（分钟）

- 每家店分别计时，从这家**发出询价**的时刻算起。
- 这段时间内没有人工回复的，这家结束：完全没回复的记「未回复」，只回了机器人消息的记「自动回复」。机器人回复（如「您好，稍等」「亲，在的」、带「智能客服」标记的消息）不算人工回复，也不重新计时。
- 默认 5 分钟。人工客服大多在 1 分钟内首次回复，个别要几分钟。

### followUpReplyMinutes：追问后等回答的时间（分钟）

- 每家店分别计时，从这家**发出追问**的时刻算起。
- 这段时间内没回答的，这家按已有信息结束，缺的项货况记「待确认」、货期留空，不道谢。
- 默认 3 分钟。追问时人工客服已在线，大多 1 分钟内回答。

> 两个等待时间之外，只有一个总的上限：任务的报价截止时间前 5 分钟，所有还没结束的店一律按已有信息结束。所有店都结束后立刻填报，不必等满。

### pollIntervalSeconds：查看回复的间隔（秒）

- `min`：最短间隔；`max`：最长间隔。
- 从最短间隔开始查；连续没有新回复，逐步拉长到最长；一有新回复，缩回最短。
- 建议 `min` 不低于 10。查得太频繁会增加平台风控的风险，也更费 AI 用量。

### maxFollowUpsPerShop：每家店最多追问几次

- 询价话术本身不算追问。默认 1 次：店家漏答的价格、含税、货况、货期，合成一句问一次。
- 道谢、发错对象后的更正消息都不算追问。
- 建议 0 到 2。设为 0 表示只发询价话术、不追问，漏答的项留空。

### dedupeDays：多少天内不向同一家店重复询价同一型号

- 本机记录里，同一型号在这么多天内问过的店家，这次不再发消息：
  - 当时报过价的，直接沿用那次报价，备注写明「沿用 x 月 x 日回复」；
  - 当时没回复的，这次跳过。
- 按型号判断：同一家店问的是其他型号，照样询价。型号比较时忽略大小写和连字符等符号（`6ES7214-1AG40-0XB0` 与 `6ES72141AG400XB0` 算同一型号），不区分平台和任务。
- 设为 0 表示不防重复，每次都重新问。
- 记录只在本机，换电脑或别的采购问过，不会被识别。

### priceOutlierPercent：价格异常的判断标准（百分比）

- 某家的不含税单价比其他店的中位价低这么多以上，标为「价格异常」（可能是假货、翻新或标错价），写进该条报价的备注，并在汇报里提醒。
- 默认 30：中位价 2000 时，低于 1400 就标出。
- 只提醒，不会删掉这条报价。

### thankYouMessages：信息齐全后的道谢说法

- 店家把单价、是否含税、货况、货期都答齐后，AI 从这里挑一句发给店家，表示这家的询价结束。含税但没说票种也算答齐（按 13% 记并备注「票种未说明」）。同一个任务里尽量不重复，避免几家店收到一模一样的话。
- 信息不齐、没回复、只有机器人回复，或者店家已经结束聊天的，都不道谢。
- 每句要简短、礼貌，不带任何业务信息（价格、型号、公司名）。至少保留 3 句。

### subagents：是否用子代理并行询价

| 键 | 默认值 | 含义 |
|---|---|---|
| `enabled` | `true` | `true`：本次启用两个及以上平台、且所用的 AI 支持子代理时，每个平台派一个子代理同时询价；否则用单代理交替推进。`false`：一律用单代理交替推进 |
| `claude.model` | `"sonnet"` | 在 Claude Code 里运行时，平台子代理用的模型（`sonnet`、`opus`、`haiku`）。留空表示沿用主代理的模型 |
| `claude.effort` | `"medium"` | 在 Claude Code 里运行时，平台子代理的思考深度（`low`、`medium`、`high`、`xhigh`、`max`）。留空表示沿用默认值 |
| `codex.model` | `"gpt-6.1-sol"` | 在 Codex 里运行时，平台子代理用的模型 ID；以当前会话可用模型为准。留空时不传模型覆盖，沿用当前 Codex 的子代理默认值 |
| `codex.effort` | `"medium"` | 在 Codex 里运行时，平台子代理的思考深度；该默认模型支持 `low`、`medium`、`high`、`xhigh`、`max`、`ultra`，其他模型以当前工具声明为准。留空时不传深度覆盖，沿用当前 Codex 的默认值 |

- 主代理负责读任务、ERP 填报和提交，沿用采购开会话时选择的模型和思考深度，本文件只配置平台子代理。Claude Code 主代理建议用 Opus 5.5；Codex 主代理按当前会话选择，本技能不改全局配置。
- Claude Code 平台子代理默认 `sonnet` / `medium`：子代理要判断机器人回复、错别字、信息是否齐全，还要对真实商家发消息。改成 `haiku` 更省，但判断出错的风险更大；改成 `opus` 更稳，用量更大。
- Codex 平台子代理默认 `gpt-6.1-sol` / `medium`，用于需要理解商家回复并连续操作网页的任务。
- 两边的默认值都是维护默认值，实际询价效果仍需实跑验证。较高思考深度可能改善复杂判断，也会增加耗时和用量。
- 这些键是技能读取的配置，Claude Code 和 Codex 都不会自动加载本文件。主代理在派发时传入：Claude Code 把 `model`、`effort` 传给 Agent 工具的同名参数，Codex 把 `model` 传给模型参数、`effort` 映射到 `reasoning_effort`。具体方式见 `SKILL.md`「Claude Code 派发与续跑」「Codex 派发与续跑」。配置不可用时不要悄悄换模型或声称配置已生效，按对应一节降级并说明。
- 留空项不传覆盖值，空字符串不能当作有效参数传入。继承规则以客户端的实际工具声明和配置为准：Codex 的 `collaboration.spawn_agent` 省略这两个参数时继承主代理的对应设置。切换模型但留空深度时，还要核实继承的深度是否受该模型支持；自定义代理配置也可能覆盖派发参数。
- Codex 模型与子代理配置依据：[OpenAI 官方子代理说明](https://learn.chatgpt.com/docs/agent-configuration/subagents)、[模型说明](https://learn.chatgpt.com/docs/models)。
