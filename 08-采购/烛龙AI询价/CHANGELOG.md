# 烛龙AI询价 · 版本变化

每次发放新版时在最上面加一条，写明这一版改了什么。正文文档（SKILL.md、references、platforms）只描述当前版本。

## 1.4.0（2026-10-16）

- 货源直达链接改为读出地址、在 AI 自己的标签页里打开，不在 ERP 页面上点击（点击打开的页面在 BrowserOS 里显示为用户的标签，站点脚本不会自动加载）。
- 设置项 `shopsPerChannel` 改名为 `shopsPerLink`，含义改为**每条货源直达链接**询价几家店（原为每个平台）：同平台的每条链接都要打开，按页面顺序一条一条做，每条从自己的搜索结果里挑这么多家，同平台有几条链接都兼容。不再「第一条链接有匹配就停」。后面的链接关键词更宽，型号仍按原型号逐字核对。总询价家数约等于链接条数乘以这个数。
- 同一型号的不同链接搜到同一家店只问一次：后面的链接跳过它，按顺序取下一家补足；前面判断过的商品 ID 直接跳过；防重复要跳过的店也跳过；遇到沿用的店计入这条链接的家数。不同型号搜到同一家店的，合并成一条消息问，这家店在每个型号里都算一家。

## 1.3.0（2026-10-16）

- 发给店家的消息按类型重新规定（规则第 4 节）：只发首次询价、追问、答复、道谢、发错更正五类。原则是像熟练的采购员那样说话：第一次联系礼貌、问清楚，之后简短直接，只去掉多余信息，不去掉礼貌用语。
- 首次询价必须包含问候、型号和数量、四项必要信息（单价、是否含税、是否全新原装、货期）。系统话术或模板缺哪样就在原话术上自然补哪样，不在末尾另起一句；型号、品牌、数量、单位一字不差，原有问题和说法保留，可调整语序和连接词。取消「末尾一律补问是否全新原装」的临时规则（ERP 数量大于 1 的话术已经问了新旧，一律补会重复）。多型号模板保持 SOP 原样，补充品牌不同时的写法。
- 追问只问还缺的项，不复述店家已经给出的价格、数量、运费、现货等，也不要求店家再确认；单项问法改得更简短。
- 新增答复：店家提问时，在可回复范围内（型号、品牌、数量和单位、任务描述里的规格、含税要求、新旧要求）且这个话题没答过，就简短回答，不计追问次数；超出范围或重复提问，停止和这家聊天。店家问新旧时答「要全新原装正品」，之后店家回「有的」或直接报价的，货况按「全新原装」记，备注写明店家原话和我们的答复。`run.json` 新增 `answeredTopics`，`endReason` 新增「答复后超时」「店家提问超出范围」「店家重复提问」；`followUpReplyMinutes` 同时用于追问和答复后的等待。
- 停止聊天时按问题类型记进 `run.json` 的 `stopQuestion`（交期要求、付款方式、下单等），`records.mjs finish` 把结束原因和问题类型写进询价记录；新增 `records.mjs stats [天数]`，统计各结束原因和停止聊天的问题类型占比，供维护者决定是否扩大答复范围（使用手册 7.1）。「什么时候要货」等交期问题目前仍算超出范围。
- 任务里原有的草稿报价原样一并提交，不再告知、不等确认，也不修改草稿内容。
- 店家没说是否含税的，按不含税填，备注「未说明是否含税」。
- 防重复：7 天内问过同一型号、当时没报价的店（没回复、无货、因提问停止聊天等）这次都不再问，挑店时跳过并换下一家。
- 道谢说法精简为 3 句短句（「好的，谢谢！」「收到，谢谢！」「谢谢！」），去掉「麻烦您了」「辛苦了」这类客套；发错更正改为「不好意思发错了」。
- `run.json` 每家店新增 `inquiry`，记录系统原话术、实际发出的话术和补了哪些内容。
- 文档不再把使用技能的人限定为「采购」：给 AI 的文档统一称「用户」，使用手册直接对读者称「你」，「采购负责人」改为「维护者」；技能说明（description）也改为「用户」，任何岗位的人说「帮我询价」都能触发。业务名词（08-采购、《采购岗位 SOP》、采购价、ERP 的采购账号）保留。

## 1.2.2（2026-10-15）

- 使用手册和设置说明里 `dedupeDays` 的描述补上「同一型号」：防重复按型号判断，同一家店问过某个型号，7 天内不再问这个型号，其他型号照样询价。询价行为不变。

## 1.2.1（2026-10-15）

- 补齐 Codex 平台子代理默认配置：`gpt-6.1-sol` / `medium`，同步设置说明与使用手册。
- 补充 Codex 派发参数、无历史上下文时的任务交接、状态检查与续跑方式；配置或工具不可用时明确降级，不修改全局 Codex 配置。
- 修正并行执行说明：平台子代理只写各自记录，由主代理合并填报；恢复或降级前确认旧执行停止；开启发送前确认时汇总所有平台一次确认。
- 明确浏览器共享会话的边界，只处理本次负责的标签，保留采购和其他任务原有标签；这条适用于所有子代理。
- 补充 Claude Code 派发与续跑：Agent 工具的 `model`、`effort` 参数，后台运行，用 SendMessage 让原子代理接着做，用 TaskStop 停止。
- 修正防重复一步：用子代理时，沿用的报价由子代理写进 `run-<平台>.json`，主代理不写进 `run.json`，避免合并时被覆盖。
- 设置说明补回 Claude 子代理的选型取舍，派发参数的说明改为同时覆盖 Claude Code 和 Codex。
- 沿用的报价记下原报价时间（`reusedFrom`），`records.mjs finish` 按原时间写记录，过了 `dedupeDays` 天就重新询价，不再被一直沿用。
- 报价截止时刻改为按读任务时的 `remainingMinutes` 算出，写进 `run.json` 的 `deadline`（ERP 的 `quoteDeadline` 只有日期）。
- `records.mjs merge` 检查 `run.json` 里每个平台都有记录文件，合并结果校验通过后才写入；不通过时报错，`run.json` 保持不变。
- 首次人工回复、追问回答是否超时，按店家消息上显示的时间判断，不按读到的时间。
- 用子代理时，实跑报告的阶段耗时按平台取自 `platformStages`。
- 平台说明里还没实跑过的做法标为「未实测」。用子代理做了一次不发消息的实测后更新：关掉旧聊天页后新页保持连接（已实测），关掉旧页后在新页发送仍未实测。
- 确认淘宝的结束信号：店家客服发的「您对客服的服务满意吗」（带满意度选项）；1688 的「客服评价邀请」只出现在会话列表预览里。两个信号都由店家客服主动发出，不一定会出现，没出现的店照常按计时和信息是否齐全结束。
- 新增 1688 的 3 个只读站点脚本：`searchCandidates`（前 20 条）、`imPreviews`、`imOpenAndRead`（返回列表预览和是否已结束）。
- 点「客服」打开的聊天页显示为采购的标签页，BrowserOS 不会在上面自动加载站点脚本；平台说明写明了手动加载的方法。
- `name_session` 的名称改为含英文字母或数字的「inquiry <任务编号>」，纯中文名称会被拒绝；补充会话句柄可能变化、关闭标签时容错的说明。

## 1.2.0（2026-10-15）

- 启用 1688：新增 `platforms/1688.md`（登录判断、挑店、聊天页、输入框定位、机器人标记和结束信号）。
- 跟进回复改为每家店分别计时：新增 `firstHumanReplyMinutes`（首次人工回复等待，默认 5 分钟）和 `followUpReplyMinutes`（追问后等待，默认 3 分钟），删除 `replyTimeoutMinutes`。所有店都结束后立刻填报；报价截止前 5 分钟为总上限。
- 店家发出结束信号（如 1688「客服评价邀请」）后，这家立即结束，不再发送任何消息。
- 只有机器人回复、超时仍无人工的店，记为「自动回复」并跳过；规则里补充机器人回复的判断方法。
- 新增店家错别字和简写的处理：结合刚问的问题理解拼音输入错字（如「型号」=「现货」），备注保留原话和理解；拿不准的追问确认或记「待确认」并在备注说明。
- 信息齐全时向店家道谢：新增 `thankYouMessages`，同一任务里轮换使用；信息不齐、没回复、只有机器人回复的不道谢。
- 各平台全程只保留一个聊天页：打开新聊天页后立刻关掉旧的。
- 询价和跟进同时推进：发出一家后，准备下一家的同时处理已有回复。
- 子代理并行询价：启用两个及以上平台、且所用 AI 支持子代理时，每个平台派一个子代理；主代理负责读任务、防重复、合并、ERP 填报和提交。新增 `subagents` 设置（是否启用，以及 Claude Code、Codex 各自子代理的模型和思考深度），`records.mjs` 新增 `merge` 命令，合并各平台的 `run-<平台>.json`。
- 单代理方式下，哪个平台先挑完店就先开始给它发询价。
- 只说「含税」没说票种也算信息齐全，照样道谢。
- 商品页逐个打开，一次最多 2 个，避免触发验证码。
- 任务里已有草稿报价时，先告诉采购会一并提交。
- 平台弹出需要选择的账号设置时，停下请采购决定。
- `settings.json` 改为由维护者统一测试定版，采购不自行修改。
- 版本变化改为记在本文件。
- 新增 `使用手册.md`：给采购和维护者看的完整说明，包括用法、通用规则、各平台规则、设置、生成的文件及位置；技能有更新时同步修改。

## 1.1.0（2026-10-15）

- 从 zhul-trade-erp 仓库的 `purchaser-skills/` 迁入 zhul-skills 的 `08-采购/`，技能改名为「烛龙AI询价」（原 `zhul-trade-sourcing`），运行时第一行输出 `烛龙AI询价 v<版本号>`。已装旧名文件夹的电脑，先删掉 `zhul-trade-sourcing` 文件夹再放新文件夹。
- 本机数据目录仍是 `.zhul-trade-sourcing`，原有询价记录和经验继续可用。
- 支持 macOS、Linux：文档补充安装位置和数据目录；`records.mjs` 按系统选择 BrowserOS neo 站点脚本目录，可用环境变量 `BROWSEROS_HELPERS_DIR` 指定（macOS、Linux 未实测）。
- 新增实跑报告：每次运行结束写到本机 `<数据目录>/reports/<YYYY-MM-DD>-<任务编号>.md`，`records.mjs init` 会创建 `reports/`。

## 1.0.0（2026-10-15）

- 按 ERP 在线流程整体改写：AI 读取「我的询价」任务，在任务页面填报价并直接提交回价，不再下载和上传 Excel 询价包（删除 `package.mjs`）。
- 一次只跑一个任务，任务内各启用平台同时询价；`platforms/` 下有说明文件的平台才启用。
- 新增 `confirmBeforeSend` 开关（默认自主执行）和 `references/settings.md`；每个平台默认询价 3 家。
- 发送前核对会话标题、发送后读回；发错对象时只发一句固定更正。
- 读到回复后点开会话清红点；挑店参考回复和发货速度；价格异常按中位价判断；补充 ERP 页面填写要点。
- 技能自带 3 个只读淘宝站点脚本（`helpers/`），由 `records.mjs install-helpers` 安装；本机记录已处理任务，避免重复跑。
