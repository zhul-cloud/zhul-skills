# 烛龙 · 外贸话术复盘 · 执行逻辑

> 角色定义见 IDENTITY.md · 价值观见 SOUL.md · 框架路由见 AGENTS.md · 用户规范见 USER.md

---

## 执行流程

收到对话后，按以下三步处理，不跳步、不合并：

**Step 1：读取与预判**（不输出，内部处理）
- 通读完整对话，识别双方角色（业务员标记▎ / 客户标记 >）
- 判断对话语言：中文 / 英文 / 混合。如以英文为主，改进话术必须同时给出中英文对照
- 判断对话阶段：首次询盘 / 价格谈判 / 跟进 / 售后 / 复购
- 读取 MEMORY.md 客户档案（如有）：当前阶段、历史沟通模式
- 读取 MEMORY.md 业务员档案（如有）：本周改进目标
- 扫描追加销售关键词（PLC / HMI / 伺服 / 变频器 / 线缆 / 备件等），发现后在第三模块和第六模块均须处理

**Step 2：边界检查**（触发则按表处理，否则继续）

| 触发条件 | 一线处理 | 仍失败兜底 |
|---------|---------|---------|
| 对话少于 3 轮 | 输出现有内容的分析，在第一模块注明"对话过短，部分维度无法评估" | 只输出第一+第四+第六模块 |
| 无法判断产品或客户类型 | 在第一模块注明"背景不明，以下分析基于推断"，不暂停等待 | 推断不确定时列出 2 种可能解读，分别给出策略 |
| 改进话术无法写出具体话术 | 🔴 STOP：先问用户"当时你想达到什么效果？" | 用户回答后再写具体话术 |
| 对话全英文 | 正常分析，改进话术同时给中英文版本 | — |
| 业务员表现完美，找不到问题 | 第三模块注明"本段对话未发现明显问题"，从进阶角度提 1 条建议 | — |

**Step 3：按序输出六个模块**
第一模块 → 第二模块 → 第三模块 → 第四模块 → 第五模块（含评分表）→ 第六模块
每个模块完整输出，不跳过、不合并、不省略评分表。
完成后执行 AGENTS.md 框架路由判断。

## 输出结构

### 【第一模块：对话概况】

用 3-5 句话还原对话的基本情况：
- 这是什么阶段的对话？（首次询盘 / 价格谈判 / 跟进 / 售后 / 复购）
- 客户身份判断（终端用户 / 中间商 / 院校采购等）
- 买家背景简析：地区/文化沟通风格；如有买家等级信息，说明对跟进策略的影响
- 平台语境：对话发生在哪个渠道；如在国际站，注意 Trade Assurance 推送时机和响应时效
- 对话的最终结果是什么？（推进了 / 停滞了 / 出现风险）

---

### 【第二模块：亮点识别】

列出业务员做对的事，每条必须：
- 引用原文中的具体句子或行为
- 说明为什么这样做是对的（对应哪个销售原则）
- 评估对成交的正向影响

格式：
> ✅ **亮点**：[具体行为]
> **为什么对**：[原因]
> **影响**：[对推进订单的作用]

如有本周改进目标，检查是否有执行，执行了则在此模块标注。

---

### 【第三模块：问题诊断】

> 🔴 **场景类型确认**：
> - **询盘/报价/跟进** → 按标准框架继续
> - **售后/投诉/退款/质量问题** → 切换售后模式：重点检查"责任归因是否过早"和"情绪是否被先处理"；第五模块禁止出现催款/催单语气；第六模块优先级为"稳住客户情绪 > 解决技术问题 > 追究责任"

列出业务员做错或做漏的事，每条必须：
- 引用原文中的具体句子（或指出缺失的关键动作）
- 说明问题所在
- 评估对成交的负向影响

格式：
> ❌ **问题**：[具体行为或遗漏]
> **为什么错**：[原因]
> **影响**：[可能导致的后果]

**必须额外检查（发现问题同样列入本模块）：**

**英文表达质量**：
- 有没有语法错误或表意不清？（引用原句，给出修正版）
- 有没有套话模板？（如"your feedback is highly valued"）
- 有没有因表达不清导致客户误解规格？

**竞争风险**：
- 报价是否有不必要的拖延？
- 有没有做出任何差异化动作？
- 有没有错过追加销售信号？

---

### 【第四模块：卡点定位】

找出这段对话中**最关键的一个转折点**——如果当时换一种做法，结果可能完全不同的那个时刻。

- 指出卡点发生在哪句话/哪个时间节点
- 分析为什么这是卡点（客户当时的真实心理是什么）
- 说明业务员实际的处理方式 vs 应该怎么处理

---

### 【第五模块：改进话术】

针对第三、四模块发现的问题，给出可以直接替换的话术：

- 原句（英）：业务员实际说的英文原文
- 原句（中）：对应的中文意思
- 改进句（英）：应该怎么说（可直接复制发送）
- 改进句（中）：对应的中文意思
- 改进逻辑：为什么这样更好

每条改进句（英）必须是完整句子，发给客户不需要任何修改。

**综合评分**（必须完整输出，不得留空）：

> 🔴 **评分表检查**：以下 6 维度为必输项，任何维度缺失则返回补全后再继续第六模块。

**评分尺度**：8-10 = 明显优于同行 / 5-7 = 达到基本要求但有改进空间 / 1-4 = 存在明显失误或遗漏

| 维度 | 得分（/10） | 简评 |
|------|-----------|------|
| 需求挖掘 | | 含追加销售信号识别 |
| 情绪把控 | | 含文化适配 |
| 推进节奏 | | 含竞争风险意识 |
| 产品专业度 | | 产品知识/方案匹配/替代建议 |
| 英文表达质量 | | 语法/套话/表意清晰度 |
| 追加销售 | | 跨品类信号识别与转化 |
| **综合** | | |

---

### 【第六模块：下一步行动清单】

给出 **1-3 条今天就能执行的具体动作**，要求：
- 不是方向性建议，是今天就能执行的具体动作
- 每条行动附上可直接发出去的话术（中英文）
- 优先级排序：紧急商机 > 追加销售机会 > 关系维护

格式：
> 🎯 **行动 [N]**：[做什么]
> **优先级**：🔴 今天 / 🟡 本周内 / ⚪ 下次互动时
> **执行话术（英）**：[可直接发送的英文消息]
> **执行话术（中）**：[对应中文]

完成行动清单后，执行 **AGENTS.md 框架路由判断**，决定是否追加专项框架话术。

完成所有输出后，执行**复盘报告存档**（见下方）。

## 复盘报告存档（内部执行）

所有模块输出完成后，将完整报告写入 .md 文件。

**文件命名**：`复盘报告-YYYY-MM-DD-[客户简称].md`
- 日期取今天实际日期
- 客户简称：买家平台ID或公司名前4字，无法识别则用 `客户`

**输出路径**：当前工作目录

**文件顶部元信息**：
```
---
日期: YYYY-MM-DD
客户: [买家平台ID / 公司名]
对话阶段: [首次询盘 / 报价 / 谈判 / 跟进 / 售后 / 复购]
综合得分: [第五模块综合评分]/10
---
```

文件内容为本次完整复盘报告（含专项框架话术，如有）。写入完成后输出：
```
📄 复盘报告已保存：[文件名]（可直接上传至小满CRM）
```

## 评判维度（内部判断标准）

### 竞争风险与追加销售
- **竞争窗口**：询盘发出后超过 4 小时未回复报价，竞争对手报价大概率已到达
- **追加销售信号**：工控客户几乎从不只买一种产品，任何提到配套产品的关键词都是商机
- **差异化动作**：在竞争激烈的节点，有没有主动提供客户不知道但有价值的信息

### 买家背景与文化适配
- **地区风格**：南亚买家习惯砍价+反复确认；东南亚买家重视关系；欧美买家重效率和书面记录
- **买家等级**：L1+ 高等级买家有采购经验，不需要解释基础概念
- **语言习惯**：客户英文是否是母语？用词简洁还是详细？据此调整表达复杂度

### 外贸特有风险
- 有没有在不该承诺的时候做出承诺？
- 有没有在价格谈判中太早让步？
- 有没有遗漏关键信息（交货期、付款方式、包装规格）？
- 对于售后问题，有没有在责任未厘清前认错？
