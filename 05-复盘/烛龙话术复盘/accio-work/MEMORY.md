# MEMORY.md · 烛龙 · 记忆

## 记忆架构

烛龙的记忆分三层，作用域和生命周期不同：

| 层级 | 作用域 | 内容 | 保留时长 |
|------|--------|------|---------|
| 会话记忆 | 当前对话 | 阶段判断、客户背景、语言类型 | 会话结束清空 |
| 客户档案 | 跨会话 | 每个客户的历史沟通模式和当前阶段 | 长期 |
| 业务员档案 | 跨会话 | 每个业务员的改进追踪和评分趋势 | 长期 |

---

## 第一层：会话记忆

每次对话开始时初始化，会话结束时清空。

```
当前对话：
  业务员：[姓名]
  客户：[平台ID / 姓名 / 公司]
  对话阶段：[首次询盘 / 报价 / 谈判 / 跟进 / 售后 / 复购]
  对话语言：[中文 / 英文 / 混合]
  追加销售信号：[扫描到的关键词，如 HMI / 线缆 / 伺服]
  场景类型：[询盘报价 / 售后投诉]
  是否首次接触：[是 / 否]
```

---

## 第二层：客户档案

每个客户一份，跨会话持久化。

```yaml
客户ID: [平台ID或姓名]
公司: [公司名，如有]
地区: [国家/地区]
买家类型: [终端用户 / 中间商 / 院校采购]
沟通渠道: [阿里国际站 / WhatsApp / 邮件]
文化备注: [如：南亚买家，习惯砍价+反复确认]

历史记录:
  - 日期: 2026-08-01
    事件: 首次询盘
    产品: Siemens S7-1200 CPU 1214C
    结果: 报价发出，等待回应
  - 日期: 2026-08-03
    事件: 第一轮跟进
    产品: 同上
    结果: 客户回复砍价

当前阶段: Stage03 · 客户谈判砍价
下一步行动: 做 I 问题建立价值，守价
注意事项: 客户对货期敏感，曾提到"项目有截止日期"
```

## 记忆更新规则

| 触发事件 | 更新内容 | 执行人 |
|---------|---------|-------|
| 每次复盘完成 | 更新客户档案当前阶段；将本次评分计入业务员档案本月均值 | 自动 |
| 每周五共学后 | 更新所有业务员的"本周改进目标" | 负责人手动 |
| 每月底审查后 | 锁定月度均分；标注持续低分维度；清空当月累计 | 负责人手动 |
| 客户成交 | 客户档案标注"已成交"；记录产品型号和金额 | 自动 |
| 客户流失 | 客户档案标注"流失"；记录判断依据（break-up后72小时无回应等） | 自动 |
| 客户重新联系 | 恢复客户档案活跃状态；清除流失标注 | 自动 |

## 记忆读取规则

| 场景 | 读取内容 | 用途 |
|------|---------|------|
| 复盘开始前 | 客户档案（历史阶段） | 判断这是第几轮跟进；避免重复已给出的建议 |
| 复盘开始前 | 业务员本周改进目标 | 在第二模块检查本周目标是否有执行 |
| 月度审查时 | 所有业务员档案月度均分 | 生成月度汇总表，找出持续低分维度 |
