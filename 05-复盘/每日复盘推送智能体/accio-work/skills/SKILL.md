# SKILL.md · 每日复盘推送智能体 · 执行流程

> Accio Work 版本。定时任务指令或手动指令触发后，按以下四步顺序执行。

## Step 1 · 拉取对话

**工具**：国际站生意助手插件（会话分析能力）

**操作**：获取店铺过去 24 小时所有对话记录

**输出**：按业务员子账号分组的对话列表

```
业务员：郭如（子账号 2500001419423）
  - 对话1：买家 John Smith，时间 16:32，轮次 5
  - 对话2：买家 Ali Hassan，时间 09:15，轮次 2
  ...

业务员：朱娜芬（子账号 2500001388527）
  ...
```

**异常处理**：
- 插件不可用 → 输出错误信息，本次终止
- 某业务员当天无对话 → 跳过该人，不推送

## Step 2 · 过滤 + 打标分类

**规则来源**：工作区 `SOP信号规则.md`

对每条对话先执行 **F 层过滤**，通过后再执行 **🔴🟡⚪ 打标**。

### F 层过滤（优先执行，命中则丢弃）

```
F1: 卖家回复中包含完整短语（大小写不敏感，忽略多余空格和末尾标点）：
    "sorry, this model unavailable ,cann't supply this"
    → 命中 → 丢弃该对话，不进入打标，不计入推送
```

> 后续如需追加过滤规则（如黑名单买家、特定语言等），在 SOP信号规则.md §零 的 F 层表格中追加，并在此处同步更新。

### 打标判断顺序（仅 F 层未命中的对话）

```
1. 先判断是否为 ⚪（跳过条件，排除最快）
   W1: 常规物流确认 / 已付款例行跟进
   W2: 对话 < 3 轮且内容只有地址/单号
   W3: 低意向或垃圾消息
   → 命中任一 → 标 ⚪，不再判断

2. 再判断是否为 🔴（首选条件）
   R1: 今天收到的新客户第一条消息（首次询盘）
   R2: 今天发出报价的对话
   → 命中任一 → 标 🔴

3. 最后判断是否为 🟡（次选条件）
   Y1: 买家回复但存在以下问题之一
       · 客户提问未直接回答
       · 未挖需求直接报价
       · 异议未处理
       · 语气生硬
   Y2: 最后一条买家消息距今 ≥2 天，今天准备跟进
   → 命中任一 → 标 🟡

4. 以上均不命中 → 标 ⚪
```

### 打标输出格式（每条）

```
🔴 客户 John Smith · 首次询盘
   → 买家发来询盘，尚未挖掘需求即可报价
   → 建议复盘重点：Dim1 需求挖掘
```

**存疑处理**：Y1 判断拿不准时，降档为 🟡，注明"存疑"，宁宽勿漏。

---

## Step 3 · 筛选排序

对每位业务员的打标结果执行：

```
1. 过滤掉所有 ⚪
2. 剩余按优先级排序：🔴 在前，🟡 在后
3. 同色按对话时间降序（最新在前）
4. 取前 2 条
5. 只有 1 条 🔴 → 只推 1 条（不用 🟡 凑数）
6. 全部 ⚪（或当天无对话）→ 推「今日无重点复盘项」
```

## Step 3.5 · 格式化对话原文（为烛龙粘贴准备）

筛选出的每条对话，在推送前先转换格式，生成**可直接粘贴到烛龙话术复盘的对话原文块**。

### 转换规则

数据源格式（messages_ready.compact.md 表格）→ 烛龙输入格式：

| 原字段 | 处理方式 |
|--------|---------|
| `from=buyer` | 输出为 `买家: [text]` |
| `from=seller` | 输出为 `卖家: [text]` |
| `text=[Card]` 或 `text=-` | 跳过，不输出 |
| `text` 含 `\n` | 替换为空格，保持单行 |
| `quoteMessage` | 忽略，不输出 |
| `messageId` / `isRead` | 忽略，不输出 |

### 长对话截断规则

```
总轮次 ≤ 15 条 → 输出完整对话
总轮次 > 15 条 → 只取最近 15 条
                  头部加注：（仅显示最近15条，建议在平台查看完整对话）
```

### 输出示例

```

买家: 6ES7412-5HK06-0AB0 Siemens 1  6ES7315-2EH14-0AB0 Siemens 1  6GK5108-0BA00-2AA3 Siemens 1
卖家: hi
```

### 签名计算（机器人已开启签名校验）

每次调用 Webhook 前，必须生成签名，否则请求会被拒绝（返回 9499 错误）。

```
签名密钥（Secret）：ccDwPf0fh352leUrOgzLGh（见 MEMORY.md）

计算步骤：
1. 获取当前 Unix 时间戳（秒级整数），记为 timestamp
2. 拼接字符串：string_to_sign = timestamp + "\n" + secret
3. 用 secret 对 string_to_sign 做 HMAC-SHA256 计算
4. 将结果 Base64 编码，得到 sign
```

Python 示例：
```python
import hmac, hashlib, base64, time

secret = "ccDwPf0fh352leUrOgzLGh"
timestamp = str(int(time.time()))
string_to_sign = f"{timestamp}\n{secret}"
sign = base64.b64encode(
    hmac.new(secret.encode(), string_to_sign.encode(), hashlib.sha256).digest()
).decode()
```

### Webhook 调用方式

```json
POST https://open.feishu.cn/open-apis/bot/v2/hook/407316dd-d707-41a7-b7d3-e320962b5be4
Content-Type: application/json

{
  "timestamp": "[Unix秒级时间戳，字符串]",
  "sign": "[HMAC-SHA256-Base64签名]",
  "msg_type": "text",
  "content": {
    "text": "[消息正文，含 <at user_id=...> 标签]"
  }
}
```

**失败处理**：调用失败 → 重试 1 次 → 仍失败则在执行日志中记录，继续推送下一位业务员。
