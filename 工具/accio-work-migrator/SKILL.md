# Accio Work 迁移工具

## 功能

**输入**：一个 Claude Code 格式的 SKILL.md（粘贴内容 或 提供文件路径）
**输出**：完整的 Accio Work 目录结构，含 6 个文件，可直接使用

---

## 目标目录结构

```
[skill名称]/
└── accio-work/
    ├── SOUL.md          # 核心价值观与行为准则
    ├── IDENTITY.md      # 角色定义与能力边界
    ├── AGENTS.md        # 编排层（子框架路由）
    ├── MEMORY.md        # 记忆结构
    ├── USER.md          # 用户画像与交互规范
    └── skills/
        └── SKILL.md     # 精简后的执行逻辑
```

---

## 执行流程

**Step 1：读取与识别**（内部处理，不输出）

读取原始 SKILL.md 全文，识别以下内容块归属：

| 原始内容 | 迁移目标 |
|---------|---------|
| 角色定位 / 角色说明 / "你是..." | → IDENTITY.md |
| 核心能力 / 专精场景 / 能力边界 | → IDENTITY.md |
| 涉及的框架/方法论说明 | → IDENTITY.md |
| 执行原则 / 行为准则 | → SOUL.md |
| 反例黑名单 / 不要做的事 / 禁止行为 | → SOUL.md |
| 框架路由表 / WebFetch 调用逻辑 / 子 agent 调用 | → AGENTS.md |
| 执行流程（Step 1/2/3） | → skills/SKILL.md 保留 |
| 输出结构（各模块格式） | → skills/SKILL.md 保留 |
| 边界条件 / 失败模式 / 兜底处理 | → skills/SKILL.md 保留 |
| 用户类型 / 交互格式 / 输入输出规范 | → USER.md |

🔴 **CHECKPOINT · 内容缺失判断**：以下内容在原 SKILL.md 中通常缺失，需推断创建，不得跳过：
- **MEMORY.md**：根据 skill 的跨会话需求推断（见 Step 3 推断规则）
- **USER.md**：根据使用场景推断用户画像（如原 SKILL.md 无明确用户说明）
- **AGENTS.md**：如无路由逻辑，创建最简骨架（说明"本 skill 无子框架调用"）

**Step 2：确认输出路径**

询问用户：
```
迁移目标路径确认：
  将在 [原 SKILL.md 所在目录]/accio-work/ 下创建 6 个文件。
  是否确认？或指定其他路径？
```

🔴 **CHECKPOINT · 路径确认**：等用户确认后再执行文件写入，不得跳过。

**Step 3：依次生成 6 个文件**

按以下顺序生成，每个文件完成后继续下一个，不合并输出：

```
SOUL.md → IDENTITY.md → AGENTS.md → MEMORY.md → USER.md → skills/SKILL.md
```

**Step 4：输出迁移报告**

所有文件生成后，输出简短的迁移报告（见输出格式）。

---

## 各文件生成规则

### SOUL.md · 核心价值观与行为准则

**提取来源**（按优先级）：
1. "执行原则" / "行为准则" 章节 → 直接迁移
2. "反例黑名单" / "不要做的事" 章节 → 直接迁移
3. 如无以上内容 → 根据 skill 目的推断 3-5 条核心价值观

**必须包含的结构**：
```markdown
# SOUL.md · [Skill名] · 核心价值观与行为准则

## 存在意义
[1-2句话：这个 skill 为什么存在，最终要达到什么效果]

## 核心价值观
[3-6条，每条有名称 + 说明 + 正反对比示例]

## 执行原则
[可操作的自检清单，每条对应一个具体行为]

## 反例黑名单
[表格：反模式 / 为什么不做 / 替代做法]
```

---

### IDENTITY.md · 角色定义与能力边界

**提取来源**：
1. "角色定位" / "你是..." → 迁移为"我是谁"章节
2. 涉及的框架/方法论 → 迁移为"核心框架"章节
3. "能力边界" / "不覆盖的场景" → 直接迁移
4. 触发条件 → 迁移为"触发条件"章节

**必须包含的结构**：
```markdown
# IDENTITY.md · [Skill名] · 角色定义与能力边界

## 我是谁
[角色定位，第一人称]

## 核心能力
[用 bullet 列出能做什么]

## 核心框架（如有）
[使用了哪些方法论，各自在本 skill 中的用途]

## 专精场景
[适用的场景、渠道、领域]

## 能力边界
[表格：不覆盖的场景 / 原因 / 当下建议]

## 触发条件
[什么情况触发这个 skill]
```

---

### AGENTS.md · 编排层

**提取来源**：
- "框架路由" / "路由表" / WebFetch 调用逻辑 → 直接迁移
- 如无路由逻辑 → 生成最简骨架（无子框架）

**有子框架路由时的结构**：
```markdown
# AGENTS.md · [Skill名] · 编排层

## 架构说明
[流程图：输入 → 主编排器 → 路由判断 → 子框架/结束]

## 子框架索引
[表格：框架名 / 职责 / 调用地址]

## 路由表
[表格：场景信号 / 调用框架]

## 子框架调用流程
[Step 1/2/3/4]

## 输出格式
[专项框架话术的固定格式模板]

## 路由失败处理
[表格：失败情况 / 处理方式]
```

**无子框架时的最简骨架**：
```markdown
# AGENTS.md · [Skill名] · 编排层

本 skill 为单一执行模式，无子框架调用。
所有逻辑在 skills/SKILL.md 中完整执行，无需编排层路由。

## 扩展说明
如未来需要接入子框架，在此处添加路由表和调用逻辑。
```

---

### MEMORY.md · 记忆

**推断规则**（原 SKILL.md 通常没有这部分，需根据用途推断）：

1. 判断是否需要**跨会话**记忆：
   - 需要追踪用户历史状态 → 设计"用户档案"层
   - 有任务进度需要记录 → 设计"任务档案"层
   - 无跨会话需求 → 只设计"会话记忆"层

2. 判断是否需要**会话内**状态追踪：
   - 多步骤流程 → 追踪当前步骤
   - 需要记住上文判断结果 → 追踪关键变量

**必须包含的结构**：
```markdown
# MEMORY.md · [Skill名] · 记忆

## 记忆架构
[表格：层级 / 作用域 / 内容 / 保留时长]

## 第一层：会话记忆
[会话内需要追踪的变量和状态]

## 第二层：[实体]档案（如需跨会话）
[档案结构模板，YAML 格式]

## 记忆更新规则
[表格：触发事件 / 更新内容 / 执行人]

## 记忆读取规则
[表格：场景 / 读取内容 / 用途]
```

---

### USER.md · 用户画像与交互规范

**推断规则**：
1. 从 skill 的 description 和使用场景推断有哪些用户角色
2. 通常有：主要使用者（执行操作的人）+ 管理查看者（看结果的人）
3. 如只有一种用户，写一个角色即可

**必须包含的结构**：
```markdown
# USER.md · [Skill名] · 用户画像与交互规范

## 用户角色

### 角色一：[主要用户]
**画像**：[职责、特点、技术水平]
**使用场景**：[什么时候用这个 skill]
**期望输出**：[最想得到什么]
**不需要的输出**：[什么对他们没价值]

### 角色二：[管理/查看用户]（如有）
...

## 交互规范

### 输入格式
[用户应该如何提交，示例]

### 输出格式选择规则
[表格：情况 / 输出格式]

### 语言规范
[表格：输出内容 / 语言]
```

---

### skills/SKILL.md · 执行逻辑

**保留规则**：从原 SKILL.md 中保留以下内容，删除已迁移到其他文件的部分：

✅ 保留：
- Frontmatter（name / description）
- 执行流程（Step 1/2/3 及其子步骤）
- 输出结构（各模块/章节的格式规范）
- 边界条件与失败模式
- 内部判断维度（评判标准、评分规则等）

❌ 删除（已迁移）：
- 角色定位 → 改为一行注释：`> 角色定义见 IDENTITY.md · 价值观见 SOUL.md · 路由见 AGENTS.md`
- 执行原则 / 反例黑名单 → 已在 SOUL.md
- 框架路由表 → 已在 AGENTS.md
- 框架/方法论说明 → 已在 IDENTITY.md

## 输出格式（迁移报告）

所有文件生成后，输出：

```
✅ 迁移完成

目录：[accio-work/ 的完整路径]
生成文件：
  SOUL.md        [N行] — [一句话说明主要提取/推断了什么]
  IDENTITY.md    [N行] — [一句话说明主要提取/推断了什么]
  AGENTS.md      [N行] — [有路由/无路由]
  MEMORY.md      [N行] — [几层记忆结构]
  USER.md        [N行] — [几个用户角色]
  skills/SKILL.md [N行] — [保留/删除了什么]

⚠️ 需要人工确认的内容：
  [列出推断创建的内容，建议用户验证是否准确]
```

## 失败路径速查表

| 触发条件 | 一线修复 | 仍失败兜底 |
|---------|---------|-----------|
| 原 SKILL.md 内容极少（<30行），难以拆分 | 生成最简六文件骨架，在每个文件中注明"需人工补充" | 只生成 skills/SKILL.md（原样复制）+ 其他五文件骨架 |
| 原 SKILL.md 没有角色定位 | 根据 description 推断，在 IDENTITY.md 顶部注明"以下角色定义基于 description 推断" | 留空"我是谁"章节，提示用户填写 |
| 原 SKILL.md 没有价值观/原则 | 根据 skill 用途推断 3-5 条，在 SOUL.md 顶部注明"以下价值观基于 skill 用途推断" | 生成通用价值观骨架 |
| 用户指定路径不存在 | 🔴 STOP：提示用户确认路径，不自动创建多层目录 | 等用户提供正确路径再继续 |
| 原 SKILL.md 内容与多个文件重叠，无法清晰归类 | 在迁移报告中注明哪些内容做了主观归类决定，建议用户复查 | — |

## 反例黑名单

| # | 反模式 | 为什么不做 | 替代做法 |
|---|--------|-----------|---------|
| 1 | 不确认路径直接写文件 | 可能覆盖已有内容 | Step 2 必须先确认路径 |
| 2 | 把原 SKILL.md 所有内容全塞进 skills/SKILL.md | 失去拆分的意义 | 严格按保留规则删除已迁移内容 |
| 3 | MEMORY.md 和 USER.md 留空说"需用户自行填写" | 这两个文件缺失会让 accio-work 智能体无法正常运行 | 基于 skill 用途推断，给出合理初稿 |
| 4 | AGENTS.md 在无路由逻辑时省略不创建 | 目录结构不完整，后续扩展困难 | 始终创建，无路由时用最简骨架 |
| 5 | 一次性输出所有文件内容让用户自己复制 | 容易出错，格式难以保证 | 使用 Write 工具逐文件创建 |
